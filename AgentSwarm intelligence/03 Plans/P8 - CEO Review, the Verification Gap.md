# CEO Plan: Close the Verification Gap

Generated by /plan-ceo-review on 2026-08-01
Branch: main | Mode: SCOPE EXPANSION

## The finding

Thirteen milestones shipped. Zero days of real usage. Four exit tests unrun. The
baseline log has been armed since 2026-08-01 and holds **zero entries**.

The number that matters is not the milestone count. It is this: **the user found
five defects in minutes of looking**, all in code I had marked verified.

| bug | how it was found |
|---|---|
| `agentswarm` not on PATH — documented command never existed | typing it |
| Window "not responding" — sync Tauri commands on the UI thread | using it |
| Rail close button dead — pane re-parents on mousedown, click never lands | clicking it |
| PowerShell pane borrowing another session's transcript | reading a log |
| README paths mangled by a `\a` escape | reading it |

Every one is reachable by launching the app and clicking once. **The verification
loop is broken, not the feature set.** Building M14 with the same loop produces
M14-shaped bugs found the same way.

## Premise challenge

**Is "build the next milestone" the right problem?** No. Nothing in the product
decays if feature work stops. What decays is the credibility of the word
"verified", and it has already decayed to zero — the last three commits on `main`
are bug fixes for things found by looking.

**What happens if we do nothing?** A working terminal with a semantic layer
nobody else has, and no evidence anyone can use it.

## The 10x vision

Open the app tomorrow and *know* it works — because the last build produced a
recording of the app being driven: launched from a cold shell, a swarm opened,
panes clicked, text typed, the close button pressed, responsiveness checked.

That artifact is three things at once:
1. the **regression test** that catches all five bug classes,
2. the **demo you send a teammate** — M2's unrun exit test, unblocked,
3. the **evidence in the build log**, so "verified" is watched, not claimed.

## Accepted scope

- A driver that starts the real `agentswarm.exe` and interacts with it as a
  person does — not the harness, not stdout, the actual binary.
- Coverage aimed at the five known bug classes: launch path, UI-thread stalls,
  click targets that move under the cursor, cross-session data leakage, and
  documentation that does not match the binary.
- Recording of each run, retained as the demo artifact.
- Watchdog on responsiveness and exit code, failing with the last stdout.
- `agentswarm doctor`.
- Wired into the build so "verified" cannot be asserted without it.

## NOT in scope

- No new user-facing features. M14 waits.
- No redesign. `/design-shotgun` is a separate decision.
- Recall is untouched.

## The one thing this plan cannot buy

Usage. Even a perfect verification loop tells you the app *works*; it cannot tell
you the app is *good*. Four exit tests still need a week of real use:

- M1 — my daily driver, I do not switch back
- M2 — the demo makes one teammate say whoa *(E2 produces the artifact; a
  teammate still has to watch it)*
- M3 — five busy sessions, nothing missed
- the baseline week itself

**Recommended sequence: build this, then use it for a week.** In that order,
because the week produces design feedback instead of crash reports.
